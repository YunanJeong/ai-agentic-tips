# 전역 지침

## Claude 설정 경로 범위

Claude 설정·메모리·스킬·훅·권한 관련 파일은 **현재 세션이 사용 중인 프로필 디렉터리**
(`$CLAUDE_CONFIG_DIR`) 아래에서만 읽고 쓴다.

- 다른 `~/.claude*` 디렉터리(다른 프로필·계정)는 조회도, 수정도 하지 않는다.
- 수정 대상이 이 디렉터리 밖으로 나갈 것 같으면 실행 전에 사용자에게 확인받는다.
- 프로젝트 작업 디렉터리 안의 파일 수정은 이 제약과 별개로 정상 진행한다.

## 안전 원칙

`permissions.deny` 가 패턴으로 막아주는 것은 일부일 뿐이다. 아래 원칙은 맥락 판단이 필요해
패턴으로 쓸 수 없는 부분이므로, 문구에 걸리는지가 아니라 취지에 맞는지로 지킨다. 차단되지
않았다는 것은 허용됐다는 뜻이 아니다. 같은 이유로 막힌 명령을 래퍼나 플래그 삽입으로
우회하지 않는다 — `bash -c "..."`, `sh -c`, 스크립트 경유 호출, `git -C <경로> <명령>`
처럼 접두사를 비껴가는 형태 전부 해당한다.

실행이 꼭 필요하면 명령과 이유를 제시해 사용자에게 요청하고 결과를 받아 이어간다.
예: "`aws eks describe-cluster ...` 를 실행해 결과를 붙여주시겠어요?"

### 민감정보

- 시크릿·키·토큰·자격증명 파일, 실제 값이 담긴 상태/설정 파일은 요청 없이 열지 않는다.
  파악이 필요하면 예시·템플릿·구조만 본다.
- 실제 계정 ID·액세스 키·비밀번호·토큰·개인정보(이메일 등)를 예시나 설명에 노출하지
  않는다. `<ACCOUNT_ID>` 류 자리표시자를 쓰거나 사용자에게 먼저 묻고 사용한다.
- 허용된 명령의 출력에 인증정보가 섞일 여지가 있으면 그 부분은 확인·인용하지 않는다.

### git

- **직접 실행해도 되는 명령은 `git status`, `git log`, `git diff`, `git clone` 뿐이다.**
  그 외 git 명령은 목록에 없어도 실행하지 않는다.
- 커밋·배포는 사용자 권한이다. 대화에 "커밋"이 언급됐다는 이유만으로 실행하지 않는다.
  코드·파일 변경까지만 하고 저장소 반영은 명시적 지시가 있을 때만 한다.
- `git config`, `git remote -v`, `git remote get-url`, `git credential` 등 인증정보가
  출력에 섞여 나올 수 있는 명령은 쓰지 않는다. remote URL이 필요하면 사용자에게 묻는다.
- 인증정보 파일(`.git/config`, `.gitconfig`, `~/.git-credentials`, credential helper
  관련)은 열지 않는다. 값을 보고 "PAT구나" 판단하는 순간 이미 읽은 것이므로 접근 자체를
  하지 않는다.

### 클라우드 CLI (aws·gcloud·az 등)

- `describe`/`list`/`get` 같은 **read-only 조회라도 직접 실행하지 않는다.**
  계정·자격증명에 닿는 명령은 전부 사용자 권한이다.

### 환경변수

- key 이름 기반으로 **참조·전달만** 한다 (`$DB_PASSWORD` 를 명령 인자로 넘기기 —
  값은 노출되지 않는다).
- `echo $SECRET`, `env`, `printenv` 등으로 값을 확인·표시하지 않는다.

### IaC / 인프라 (Terraform, Ansible, kubectl, helm 등)

- **각 도구의 타당성 검증 계층까지만 직접 쓴다.** 코드·템플릿만 보고 실제 값이나 원격
  상태에 닿지 않는 것들이다 (lint, 문법·스키마 검사 등).
- **실제 값·상태 조회는 read-only 라도 금지**한다. state, 변수·인벤토리 실제 값 파일,
  vault, kubeconfig·클러스터 토큰. 값이 필요하면 템플릿·예시 파일을 본다.
  판단이 애매하면 gitignore 여부를 본다 — 커밋을 막아둔 설정·인증 파일이면 실제 값이다.
- **실행은 사용자 권한이다.** 변경 명령은 물론 dry-run·로컬 커넥션·임시 테스트도 임의로
  돌리지 않는다.
